# **System Requirements Document (SRD) для сервиса учёта тренировок**

## 1. **Введение**

### 1.1 **Цель документа**

Цель данного документа — описать системные требования для разработки сервиса учёта тренировок, который будет реализован на платформе **Java Spring**. Он определяет функциональные и технические требования, архитектуру системы и спецификации, необходимые для эффективной реализации проекта.

### 1.2 **Общие сведения о системе**

Система учёта тренировок предназначена для помощи пользователям в планировании и отслеживании их физических тренировок. Включает в себя функционал для регистрации, управления тренировками (workout), упражнениями (exercise), отслеживания прогресса (progress), а также безопасное хранение данных пользователей и их тренировок.

### 1.3 **Аудитория документа**

Документ предназначен для разработчиков, архитекторов, тестировщиков и руководителей проекта, а также для всех участников процесса разработки.

---

## 2. **Общие требования**

### 2.1 **Тип системы**

Система будет представлять собой **веб-приложение**, реализованное с использованием **Java Spring Framework** для серверной логики и **PostgreSQL** для хранения данных.

### 2.2 **Платформа и технологии**

* **Backend:** Java Spring Boot, Spring Security, Spring Data JPA, Spring Validation
* **База данных:** PostgreSQL
* **Система контроля версий:** Git

### 2.3 **Ожидаемые объемы нагрузки**

* Система должна быть масштабируемой для работы с количеством пользователей от 100 до 10,000.
* Ожидаемая нагрузка: до 1000 запросов в минуту.

---

## 3. **Функциональные требования**

### 3.1 **Регистрация и аутентификация пользователей**

* Пользователи могут зарегистрироваться в системе с помощью имени, электронной почты и пароля.
* Система поддерживает функциональность авторизации с использованием email и пароля.
* Пароли должны храниться в зашифрованном виде.
* Использование **JWT** (JSON Web Token) для управления сессиями пользователей.

### 3.2 **Управление тренировками (Workout), упражнениями (Exercise) и прогрессом (Progress)**

* **Workout (Тренировка):**

    * Пользователь может создать тренировку, указав только **имя тренировки** и **дату**.
    * Упражнения для тренировки можно добавлять **позднее** через отдельные запросы.
* **Exercise (Упражнение):**

    * Упражнение связано с конкретной тренировкой. Каждое упражнение имеет название и связь с повторениями.
* **Progress (Прогресс):**

    * Прогресс можно отслеживать только для каждого упражнения.
    * Прогресс включает количество выполненных повторений, вес и другие метрики.
    * Прогресс может быть добавлен, изменен или удален только для существующих упражнений.

---

## 4. **Технические требования**

### 4.1 **Архитектура**

* Система должна быть построена на базе **архитектуры микросервисов** или **слойной архитектуры**, где каждый слой выполняет свою роль.
* Разделение бизнес-логики (сервисный слой), доступа к данным (репозиторный слой) и пользовательского интерфейса (веб-слой).

### 4.2 **Технологии**

* **Spring Boot** — основной фреймворк для разработки серверной логики.
* **Spring Security** — для реализации аутентификации и авторизации.
* **Spring Data JPA** — для работы с базой данных.
* **Spring Validation** - для валидации данных от пользователя.
* **PostgreSQL** — для хранения данных о пользователях, тренировках, упражнениях и прогрессе.
* **JWT (JSON Web Token)** — для реализации аутентификации.
* **JUnit** — для тестирования сервисов и логики.

### 4.3 **Требования к производительности**

* Время отклика системы не должно превышать 2 секунд для основных операций.
* База данных должна эффективно работать с большими объёмами данных.
* Реализовать возможность кэширования популярных запросов для повышения производительности.

### 4.4 **Интерфейсы**

* **REST API** для взаимодействия с фронтендом и другими сервисами.
* Все API должны быть документированы с помощью **Swagger** или **OpenAPI**.
* Поддержка форматов **JSON** для обмена данными.

---

## 5. **Не функциональные требования**

### 5.1 **Юзабилити**

* Интерфейс должен быть простым и интуитивно понятным для конечного пользователя.
* Приложение должно быть адаптивным, поддерживая работу как на мобильных, так и на десктопных устройствах.

### 5.2 **Масштабируемость**

* Система должна поддерживать горизонтальное масштабирование с возможностью добавления новых серверов при увеличении нагрузки.

### 5.3 **Надежность и отказоустойчивость**

* Важно обеспечить стабильную работу сервиса, используя механизмы балансировки нагрузки, репликации базы данных и резервного копирования.
* Все компоненты системы должны быть устойчивыми к сбоям, с возможностью восстановления данных в случае аварий.

---

## 6. **Архитектурное описание**

### 6.1 **Диаграмма архитектуры**

Визуализировать архитектуру системы с компонентами:

* **Frontend:** Пользовательский интерфейс.
* **Backend:** API, реализующий бизнес-логику (Java Spring).
* **База данных:** PostgreSQL с таблицами для пользователей, тренировок (workout), упражнений (exercise), названиями упражнений (exercise_type) и прогресса (progress).
* **Уведомления:** Механизмы напоминаний через email или push-уведомления (пока не реализованы).

### 6.2 **Основные компоненты**

* **User Service:** Управление пользователями (регистрация, аутентификация).
* **Workout Service:** Управление тренировками, добавление упражнений.
* **Exercise Service:** Управление упражнениями, добавление прогресса.
* **Progress Service:** Отслеживание прогресса по упражнениям.
* **Notification Service:** Уведомления и напоминания пользователям (не реализованы в текущем проекте).

## 7. **Описание API и URL-структуры**

### 7.1 **Основные URL API**

Ниже приведены ключевые эндпоинты API для работы с сервисом учёта тренировок.

#### 7.1.1 **Регистрация и аутентификация**

* **POST /api/auth/register**

    * Описание: Регистрация нового пользователя.
    * Тело запроса:

      ```json
      {
        "name": "user",
        "email": "user@example.com",
        "password": "password123"
      }
      ```
    * Ответ:

      ```json
      {
        "message": "User registered successfully"
      }
      ```

* **POST /api/auth/login**

    * Описание: Аутентификация пользователя (получение токена).
    * Тело запроса:

      ```json
      {
        "email": "user@example.com",
        "password": "password123"
      }
      ```
    * Ответ:

      ```json
      {
        "token": "jwt-token-here",
        "refreshToken": "refresh-token-here"
      }
      ```

* **POST /api/auth/refresh**

    * Описание: Обновление токена.
    * Тело запроса:

      ```json
      {
        "refreshToken": "refresh-token-here"
      }
      ```
    * Ответ:

      ```json
      {
        "token": "jwt-token-here",
        "refreshToken": "refresh-token-here"
      }
      ```

#### 7.1.2 **Управление тренировками (Workout)**

* **GET /api/workouts**

    * Описание: Получение списка всех тренировок пользователя.
    * Ответ:

      ```json
      [
        {
          "id": 1,
          "name": "Cardio",
          "date": "2026-02-20T10:00:00",
          "createdAt": "2026-02-16T23:03:12.044261"
        }
      ]
      ```

* **GET /api/workouts/{workoutId}**

    * Описание: Получение тренировки по ID.
    * Параметр в URL: `{workoutId}` — ID тренировки.
    * Ответ:

      ```json
      {
        "id": 1,
          "name": "Cardio",
          "date": "2026-02-20T10:00:00",
          "createdAt": "2026-02-16T23:03:12.044261"
      }
      ```

* **POST /api/workouts**

    * Описание: Создание новой тренировки. Требуется только имя тренировки и дата.
    * Тело запроса:

      ```json
      {
        "name": "Strength Training",
        "date": "2026-02-20T10:00:00"
      }
      ```
    * Ответ:

      ```json
      {
        "message": "Created successfully"
      }
      ```

* **PUT /api/workouts/{workoutId}**

    * Описание: Редактирование существующей тренировки по ID.
    * Параметр в URL: `{workoutId}` — ID тренировки.
    * Тело запроса:

      ```json
      {
        "name": "Updated Strength Training",
        "date": "2026-02-21T10:00:00"
      }
      ```
    * Ответ:

      ```json
      {
        "message": "Updated successfully"
      }
      ```

* **DELETE /api/workouts/{workoutId}**

    * Описание: Удаление тренировки по ID.
    * Ответ:

      ```json
      {
        "message": "Deleted successfully"
      }
      ```

#### 7.1.3 **Управление упражнениями (Exercise)**

* **GET /api/exercises/{workoutId}**

    * Описание: Получение списка всех упражнений для конкретной тренировки.
    * Параметр в URL: `{workoutId}` — ID тренировки.
    * Ответ:

      ```json
      [
        {
        "exerciseType": {
            "id": 2,
            "name": "Отжимания"
        },
        "createdAt": "2026-02-20T21:10:52.186826",
        "id": 1
        }
      ]
      ```

* **POST /api/exercises/{workoutId}**

    * Описание: Добавление нового упражнения в тренировку по ID.
    * Тело запроса:

      ```json
      {
        "name": "Push-up"
      }
      ```
    * Ответ:

      ```json
      {
        "message": "Exercise added successfully"
      }
      ```

* **PUT /api/exercises/{exerciseId}**

    * Описание: Обновление упражнения по ID.
    * Параметр в URL: `{exerciseId}` — ID упражнения.
    * Тело запроса:

      ```json
      {
        "name": "Updated Push-up"
      }
      ```
    * Ответ:

      ```json
      {
        "message": "Updated successfully"
      }
      ```

* **DELETE /api/exercises/{exerciseId}**

    * Описание: Удаление упражнения по ID.
    * Параметр в URL: `{exerciseId}` — ID упражнения.
    * Ответ:

      ```json
      {
        "message": "Exercise deleted successfully"
      }
      ```

#### 7.1.4 **Отслеживание прогресса (Progress)**

* **GET /api/progress/{progressId}**

    * Описание: Получение прогресса для конкретного упражнения по ID.
    * Параметр в URL: `{progressId}` — ID прогресса.
    * Ответ:

      ```json
      {
          "repetitions": 123,
          "sets": 2,
          "weight": 44.0,
          "id": 1
      }
      ```

* **GET /api/progress/exercise/{exerciseId}**

    * **Описание**: Получение списка всех прогрессов для конкретного упражнения по его ID.
    * **Параметр в URL**: `{exerciseId}` — ID упражнения.
    * **Ответ**:

      ```json
        [
          {
              "repetitions": 123,
              "sets": 2,
              "weight": 44.0,
              "id": 1
          }
        ]
      ```


* **POST /api/progress/{exerciseId}**

    * Описание: Добавление прогресса для упражнения.
  * **Параметр в URL**: `{exerciseId}` — ID упражнения.
  * Тело запроса:

  ```json
  {
      "repetitions": 123,
      "sets": 2,
      "weight": 44
  }
  ```
  * Ответ:

  ```json
  {
    "message": "Created successfully"
  }
  ```

* **PUT /api/progress/{progressId}**

    * Описание: Обновление прогресса для упражнения по ID.
    * Параметр в URL: `{progressId}` — ID прогресса.
    * Тело запроса:

      ```json
      {
        "repetitions": 123,
        "sets": 2,
        "weight": 44
      }
      ```
    * Ответ:

      ```json
      {
        "message": "Updated successfully"
      }
      ```

* **DELETE /api/progress/{progressId}**

    * Описание: Удаление прогресса для упражнения по ID.
    * Параметр в URL: `{progressId}` — ID прогресса.
    * Ответ:

      ```json
      {
        "message": "Deleted successfully"
      }
      ```

## 8. **Заключение**

Данный SRD описывает основные требования и функционал для разработки сервиса учёта тренировок с использованием Java Spring и базы данных **PostgreSQL**. Включает как технические, так и функциональные требования, а также структуру API, что поможет команде разработки эффективно начать реализацию и тестирование системы.
